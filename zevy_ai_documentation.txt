ZEVY AI – TECHNICAL BLUEPRINT
Last Updated: February 2026

============================================================
1. HIGH-LEVEL OVERVIEW
============================================================

Zevy AI is a multi-model conversational AI system built by Adam Zein Ziqry. It combines:
- Multiple large language models (LLMs) running on Groq and other providers
- A knowledge integration layer called “Groq Compound”
- A debate-style reasoning engine (Vyra)
- A fast single-engine assistant (Astra)
- A shared persona / conscience layer (Axiom Core)
- A Next.js 14 frontend with a custom chat UI
- Supabase-backed authentication, usage tracking, and conversation storage

Core design goals:
- Brutally honest but reality-grounded guidance (no fake comfort, no sugarcoating)
- Deep research when Vector mode is ON, with strict factual discipline
- Clear separation between:
  - Reasoning engines (Astra and Vyra)
  - Knowledge gathering (Groq Compound)
  - Personality / conscience (Axiom Core)
  - Safety (Llama Guard and additional logic)


============================================================
2. RUNTIME ARCHITECTURE
============================================================

2.1 Frontend Layer (Next.js / React)
------------------------------------
Location: app/page.tsx and supporting components.

Responsibilities:
- Render the main chat interface (messages, input bar, presets, mode toggles).
- Allow model selection between Astra and Vyra.
- Control Vector / Web Search toggle.
- Handle document uploads (PDF, DOCX, TXT, MD, CSV, RTF) and convert to text.
- Maintain theme (dark/light), palette, and interactive teaching tools.
- Persist user settings (trait, mindset, model selection) locally and via Supabase.

The frontend defines a SYSTEM_PROMPT string that describes Zevy’s Axiom Core persona:
- Single-state Axiom Core: one consistent voice that prioritizes objective logic and “brutal truth”.
- Tone: foundational, blunt, and architect-like — no fluff, no fake friendliness.
- No slang mirroring: the assistant uses its own sophisticated, slightly cynical, high-intellect voice.
- Timezone awareness is silent: it is used when it impacts reasoning (deadlines, travel), not for greetings.
- First sentence must always deliver high value (insight, clarification, or recommendation).

Although this prompt is declared on the frontend, the actual runtime behaviour is enforced on the backend via the backend SYSTEM_PROMPT and additional prompt layers.


2.2 Backend Layer (Next.js Route Handler)
-----------------------------------------
Location: app/api/chat/route.ts

Key responsibilities:
- Accept chat requests from the frontend:
  - message
  - chat_history
  - model (astra | vyra)
  - searchEnabled / webSearch
  - mindset
  - beastMode flag
  - documents (processed text attachments)
- Resolve the effective modelType (astra or vyra).
- Run moderation (Llama Guard + custom logic).
- Invoke Groq Compound for web research when Vector is ON.
- Route to the correct reasoning pattern:
  - Astra direct response
  - Vyra dual-debate pipeline
  - Groq Compound contextualized answer
- Store and load conversation history via Supabase.
- Enforce usage limits for Astra and Vyra per user.

The backend defines its own SYSTEM_PROMPT(currentTime, timezone, searchEnabled, mindset, isBeastMode) which:
- Describes the environment (time, search status, mindset).
- Instructs the assistant to:
  - Behave as Zevy / Axiom Core.
  - Prioritize brutally honest, objective feedback over comfort.
  - Avoid repetitive greetings and bot-like pleasantries.
  - Start replies directly with the highest-value insight.
  - Avoid mirroring slang and instead use its own stable voice.
  - Mention time and timezone only when they materially affect reasoning.
  - Keep safety rules and moderation constraints in place.


2.3 Knowledge Integration: Groq Compound
----------------------------------------
Location: app/lib/groq-compound.ts

Groq Compound is the dedicated research engine that:
- Generates a focused search query from the user’s prompt.
- Calls multiple knowledge sources in parallel:
  - Custom web search (Google Custom Search or fallbacks)
  - Wikipedia (search results + page fetch)
  - News APIs (recent, relevant articles)
  - Wikidata
  - DBpedia
  - Time and date APIs (world time)
- Synthesizes all retrieved information into a structured “research context”.
- Enforces hard caps:
  - Astra: roughly 10 primary web sources.
  - Vyra: up to ~100 web sources, but only 24–40 pages are deeply fetched, with parallel HTTP fetch and capped concurrency for speed.
- Performs Wikipedia validation as an explicit double-check step.

The main exported method is:
- browseAndAnalyze(userPrompt, targetModel, forceSearch?)
  - Applies heuristics to detect when search is needed.
  - Uses a model-specific maxWebSources (100 for Vyra, 10 for Astra).
  - Fetches web results and supporting sources concurrently.
  - Truncates to a bounded dataset and analyzes it with a Groq LLM.
  - Returns a single research-backed analysis string.


2.4 Reasoning Engines: Astra vs Vyra
------------------------------------

ASTRA (Single-Engine Assistant)
- Purpose: Fast, balanced, research-focused answers.
- Models: Llama-based Groq models (scout + maverick style pairing in documentation; exact IDs configured in environment).
- Flow (simplified):
  1. Receive user message and chat history.
  2. Optionally call Groq Compound when Vector is ON.
  3. Build a contextualized prompt that includes:
     - Web Research Context (if any).
     - Previous conversation (chat_history).
  4. Call Groq with the Astra model and SYSTEM_PROMPT applied as a system-level instruction.
  5. Return a medium-length answer (2–4 short paragraphs or bullets).

VYRA (Debate Engine)
- Purpose: Deep, multi-perspective reasoning using multiple models.
- Core models (from docs and code):
  - Kimi K2 (moonshot / kimi-k2-instruct) – “Kairo”
  - Qwen 32B – “Logos”
- Flow (simplified):
  1. Gather knowledge with Groq Compound (especially when Vector is ON).
  2. Feed the same knowledge context into:
     - Kairo for bold analysis.
     - Logos for cautious analysis.
  3. Run an internal debate:
     - Kairo challenges Logos’ position.
     - Logos defends and refines its stance.
  4. Generate a closing internal argument (Kairo final).
  5. Run a final synthesis prompt that:
     - Sees all the internal analyses and debates.
     - Is instructed to answer as Zevy (Axiom Core), ignoring persona internals.
     - Prioritizes brutal truth while staying respectful and safe.
  6. Return a single user-facing answer that does not expose persona names or debate details.


============================================================
3. CONVERSATION AND CONTROL FLOW
============================================================

3.1 Request Path
----------------

Frontend (app/page.tsx):
- User picks:
  - Model: Astra or Vyra.
  - Vector / Web Search: ON/OFF.
  - Mindset (Balanced, Philosopher, Strategist, Storyteller, etc.).
  - Optional Beast Mode toggle.
- User enters message and optionally attaches documents.
- Frontend:
  - Blocks sending while documents are still being processed (uploadProgress).
  - Packs:
    - message
    - chat_history
    - model
    - searchEnabled / webSearch
    - mindset
    - beastMode
    - documents: [{ name, type, content }]
  - Sends JSON to POST /api/chat.

Backend (app/api/chat/route.ts):
- Extracts and normalizes:
  - model (astra | vyra)
  - searchEnabled (Vector toggle or webSearch boolean)
  - mindset and beastMode
  - documents array
- Runs moderation (isSafe and isPromptSafe).
- Resolves user identity:
  - session user from Supabase, or
  - “guest” for unauthenticated usage.
- Routes to:
  - Owner commands (special commands only for creator).
  - Normal chat handling via Astra or Vyra pipeline.


3.2 Search / Vector Handling
----------------------------

The system supports two modes:
- Search OFF:
  - The assistant relies only on its training and internal reasoning.
  - It must state uncertainty when information is likely outdated or unknown.
- Search ON:
  - Groq Compound is invoked from:
    - gatherKnowledge() for Astra.
    - Vyra debate path for deep reasoning.
  - For Vyra, browseAndAnalyze is called with a Vyra target model, forceSearch=true when Vector is ON.
  - For Astra, browseAndAnalyze is called with Astra target.

The resolved user message for search is produced by resolveUserMessageForSearch:
- If the user says things like “check it”, “verify that”, “is that correct?”, the function:
  - Locates the last user or assistant message in history.
  - Combines the new query with the previous content so “it” has a concrete referent.


3.3 Document Handling
---------------------

Frontend:
- Accepts file drops or file picker selections.
- Valid formats:
  - PDFs (text-based)
  - DOCX
  - TXT
  - RTF
  - Markdown
  - CSV
- For each file:
  - Reads content via FileReader.
  - Extracts and normalizes text (may involve decoding base64 for certain formats).
  - Stores attachedFiles entries with:
    - type (e.g., "pdf", "text")
    - data (text content)
    - name
    - preview (short snippet for UI).
- uploadProgress:
  - Tracks files still being processed.
  - Send button and Enter key are disabled while uploadProgress is non-empty.

Backend:
- Receives documents array in the JSON body.
- Converts into a single documentsContext string:
  - "Document 1 (name):\n<content>\n\n---\n\nDocument 2 (name):\n<content>..."
  - Truncates to a maximum length (e.g., 8k characters).
- Extends chat_history:
  - Adds an extra user message: "Attached documents:\n\n{documentsContext}".
- The final prompt given to the model always has the documents context included before reasoning, ensuring the AI reads the file content when answering the user.


============================================================
4. SAFETY AND MODERATION
============================================================

4.1 Llama Guard Content Moderation
----------------------------------

Moderation is performed in two layers:
1. isSafe(prompt: string) – runs before executing the core chat logic.
2. isPromptSafe(prompt: string, userModel: string) – additional safety checks.

Key rules:
- Clearly disallowed:
  - Real-world violent crime instructions.
  - Self-harm and suicide guidance.
  - Child sexual abuse material and related content.
  - Hacking / malware with real-world damage intent.
  - Sensitive private data leaks (passwords, credit cards, etc.).
- Explicitly allowed but monitored:
  - Non-graphic discussions of crimes and abuse (e.g., Epstein files, trafficking cases).
  - Disturbing or sad historical content with victims.
  - Non-graphic stories about evil acts and their consequences.

Custom overrides:
- Lyrical and entertainment queries:
  - If the model flags a song/lyrics request as unsafe but it’s clearly about music, the system relaxes the block.
- Metaphor handling:
  - Phrases like “this killed me”, “dying of laughter”, “destroy Grok’s answers” are treated as safe when clearly figurative.
- Legal / moral / hypothetical context:
  - Terms like “trolley problem”, “moral dilemma”, or legal scenarios can bypass overly strict unsafe flags when self-harm or explicit violence is not being requested.
- Descriptive crime requests:
  - If the user asks about stories, cases, files, victims, or reports (without asking “how to” do the crime), the system allows discussion, while still blocking self-harm or operational instructions.

In unsafe cases:
- The API returns a NextResponse with status 400 and a clear explanation.
- In ambiguous error cases (like moderation engine failure), the system often defaults to allowing the conversation but may restrict sensitive topics.


4.2 Persona Constraints and Brutal Truth
----------------------------------------

While Axiom Core is allowed to be blunt and emotionally intense, the following hard constraints always apply:
- No step-by-step guidance for violence, self-harm, terrorism, or serious crime.
- No targeted hate or slurs.
- No doxxing or invasion of privacy.
- No cheering for real-world suffering.
- When the user is in visible distress or mentions self-harm, tone must become calm, serious, and safety-first, even if the content is still honest about severity.


============================================================
5. USAGE LIMITS AND ANALYTICS
============================================================

Supabase is used to track:
- Per-user daily usage of:
  - Astra (higher limit, e.g., 125 uses/day).
  - Vyra (lower limit, e.g., 25 uses/day).
- Conversation metadata.
- Authentication sessions.

Key behaviours:
- When a limit is reached, the chat endpoint:
  - Returns a message indicating the limit was hit.
  - Refuses to process further Astra/Vyra calls for that user until reset.
- Limits reset daily.

6. UI / UX PRINCIPLES
============================================================

UI Goals:
- Make the conversation feel like sitting with a high-level architect:
  - No repeated “Hi!” or empty greetings.
  - Answers start with the core insight, then expand briefly.
- Provide quick access to:
  - Model switcher (Astra / Vyra).
  - Vector / Web Search toggle.
  - Mindset selection (Balanced, Philosopher, Strategist, Storyteller, etc.).
  - Teaching tools like flashcards and quizzes.
- Keep the screen grounded:
  - Clear separation between sidebar (conversations) and main chat pane.
  - Document attachments visible until sent, then cleared.


============================================================
7. MENTAL MODEL: HOW TO THINK ABOUT ZEVY
============================================================

Zevy is best understood as four cooperating layers running on top of each other:

1. Axiom Core (Persona / Conscience)
   - Defines how Zevy talks, what it values, and how honest it is.
   - Enforces a brutal-truth, reality-first philosophy while staying within safety rules.

2. Reasoning Engines (Astra + Vyra)
   - Decide how to think about the user’s question:
     - Fast, direct reasoning (Astra).
     - Deep, adversarial debate (Vyra).

3. Knowledge Engine (Groq Compound)
   - Collects and verifies information from the internet and open data.
   - Provides a dense research context so Astra/Vyra can think accurately.

4. Infrastructure and Governance (Supabase + Moderation)
   - Tracks usage limits, sessions, and conversations.
   - Applies moderation and safety rules at the entrance to every request.

These layers are wired together through the Next.js API route, which:
- Receives prompts and context from the frontend.
- Applies safety and routing logic.
- Calls the right models with the right prompts.
- Returns a single reply that feels like one coherent mind: Zevy.
